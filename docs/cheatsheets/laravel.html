Section 01

Basics

Project layout, environment setup, and essential artisan commands.

Tip

Run composer install, copy .env, set APP_KEY, then cache config/routes when deploying.

Project Structure

Key directories and their purpose.

  • app/: application code (Models, Http/, Providers).
  • routes/: web.php, api.php, console.php, channels.php.
  • database/: migrations, seeders, factories.
  • config/: configuration per feature (cache, queue, mail).
  • resources/: Blade views, lang, assets.
  • storage/: logs, cache, compiled views.

Create Project

Scaffold a new Laravel app via installer or composer.

  • laravel new <name>: fastest (installer required).
  • composer create-project: no installer needed.
# Using Laravel installer
laravel new blog

# Using composer
composer create-project laravel/laravel blog

Serve Locally

Run the embedded PHP server for quick dev.

  • php artisan serve: defaults to http://127.0.0.1:8000.
  • --host, --port: override host/port.
# Custom host/port
php artisan serve --host=0.0.0.0 --port=8080

Artisan List

Discover available commands and groups.

  • php artisan list: grouped commands.
  • php artisan help <cmd>: detailed usage and options.
# Show all commands
php artisan list

# View command options
php artisan help migrate

Environment & Config Cache

Manage .env, keys, and cached configuration for performance.

  • cp .env.example .env: seed environment file.
  • php artisan key:generate: set APP_KEY.
  • php artisan config:cache: compile config to bootstrap/cache.
  • php artisan route:cache: cache routes (avoid closures in prod).
  • php artisan view:cache: precompile Blade views.
  • php artisan config:clear: clear cached config.
# Prepare env and key
cp .env.example .env
php artisan key:generate

# Cache for production
php artisan config:cache
php artisan route:cache
php artisan view:cache

Section 02

Routes

Define endpoints, group middleware, and name routes for URL generation.

Reminder

Cache routes in production and avoid route closures if you plan to cache.

HTTP Verbs

Route helper methods map to verbs in routes/web.php or api.php.

  • Route::get/post/put/patch/delete
  • Route::match(['get','post'], ...)
  • Route::any: respond to all verbs.
// routes/web.php
Route::get('/health', fn () => 'ok');
Route::post('/users', [UserController::class, 'store']);
Route::match(['get','post'], '/search', SearchController::class);

Named Routes

Give routes stable names for URL generation and redirects.

  • ->name('route.name')
  • route('route.name', params): generate URL.
  • redirect()->route('route.name'): redirect helper.
// Defining names
Route::get('/profile/{user}', [ProfileController::class, 'show'])
  ->name('profile.show');

// In Blade
View

// In controller
return redirect()->route('profile.show', $user);

Route Groups & Middleware

Share middleware, prefixes, and namespaces across grouped routes.

  • ->middleware(): apply single or array.
  • ->prefix(): URL prefix.
  • ->as(): name prefix.
Route::prefix('admin')
  ->as('admin.')
  ->middleware(['auth', 'can:admin'])
  ->group(function () {
    Route::get('/dashboard', DashboardController::class)->name('dashboard');
    Route::resource('users', AdminUserController::class);
  });

Controller Routes

Point routes to invokable or controller methods.

  • Route::controller(): group common controller.
  • Route::resource(): CRUD routes for a resource.
  • Route::apiResource(): resource without view routes.
// Invokable controller
Route::get('/invite', InviteController::class);

// Resource routes
Route::resource('posts', PostController::class);
Route::apiResource('users', Api\UserController::class);

Section 03

Controllers

Organize request handling, inject dependencies, and return responses.

Note

Use invokable controllers for single-action endpoints; use resource controllers for CRUD.

make:controller

Generate controllers with helpful flags.

  • -i/--invokable: single __invoke method.
  • -r/--resource: full resource methods.
  • --model: type-hint model (route-model binding).
  • --api: generate resource minus create/edit views.
# Invokable controller
php artisan make:controller InviteController --invokable

# Resource controller with model binding
php artisan make:controller PostController --resource --model=Post

Resource Controllers

Provides index, create, store, show, edit, update, destroy.

  • Route::resource('posts', PostController::class)
  • only/except: limit generated routes.
  • Route::resources([...]): register multiple.
// Limit to index/show
Route::resource('docs', DocController::class)->only(['index','show']);

// Multiple at once
Route::resources([
  'posts' => PostController::class,
  'users' => UserController::class,
]);

Dependency Injection

Type-hint services, requests, or models; Laravel resolves them via container.

  • FormRequest: validated input.
  • Model binding: inject route model instances.
  • Service classes: bind interfaces in providers.
class PostController extends Controller
{
    public function update(UpdatePostRequest $request, Post $post, Markdown $md)
    {
        $post->update($request->validated());
        $post->body_html = $md->convert($post->body);
        $post->save();
        return redirect()->route('posts.show', $post);
    }
}

Controller Responses

Return views, JSON, redirects, or streams.

  • return view('posts.show', compact('post'));
  • return response()->json([...], 201);
  • return redirect()->route(...);
  • return response()->streamDownload(...);
public function show(Post $post)
{
    return view('posts.show', ['post' => $post]);
}

public function export()
{
    return response()->streamDownload(function () {
        echo Report::csv();
    }, 'report.csv');
}

Section 05

Models & Database

Eloquent models, relationships, migrations, factories, and seeders.

Best Practice

Use fillable/guarded for mass assignment, prefer UUIDs for distributed apps, and keep queries out of views.

make:model

Generate models with related artifacts.

  • -m: create migration.
  • -f: create factory.
  • -s: create seeder.
  • -c: create controller.
  • -a: all of the above.
# Model with migration and factory
php artisan make:model Post -mf

# Everything (migration, factory, seeder, controller, policy)
php artisan make:model Invoice -a

Eloquent Basics

CRUD with mass assignment and guarded fields.

// app/Models/Post.php
class Post extends Model
{
    protected $fillable = ['title','body','published_at'];
}

// Create
Post::create([...]);

// Read
$posts = Post::where('published_at', '<=', now())
             ->latest()
             ->paginate(10);

// Update
tap($post)->update(['title' => 'New']);

// Delete
$post->delete();

Relationships

Define relations on models for eager loading and constraints.

  • hasOne / belongsTo
  • hasMany / belongsToMany
  • morphOne / morphMany / morphToMany
  • with(): eager load; loadCount(): counts.
// app/Models/Post.php
public function author()
{
    return $this->belongsTo(User::class, 'user_id');
}

public function comments()
{
    return $this->hasMany(Comment::class);
}

// Usage
$posts = Post::with(['author','comments'])->latest()->get();

Query Builder

Chainable API for complex queries.

$users = DB::table('users')
  ->select('id','name')
  ->whereNull('deleted_at')
  ->when($active, fn($q) => $q->where('active', true))
  ->orderByDesc('created_at')
  ->limit(50)
  ->get();

Use chunk(), cursor(), lazy() for large datasets; wrap writes in transactions via DB::transaction.

Migrations

Version database schema safely.

  • php artisan make:migration create/modify tables.
  • php artisan migrate: run migrations.
  • php artisan migrate:rollback --step=1
  • --path: run specific folder.
# Create table migration
php artisan make:migration create_orders_table

# Rollback last batch
php artisan migrate:rollback --step=1

Factories & Seeders

Generate test data and initial content.

  • php artisan make:factory UserFactory
  • php artisan make:seeder UserSeeder
  • Model::factory()->count(10)->create()
  • php artisan db:seed or migrate --seed
// database/factories/UserFactory.php
public function definition()
{
    return [
        'name' => fake()->name(),
        'email' => fake()->unique()->safeEmail(),
        'password' => bcrypt('secret'),
    ];
}

// database/seeders/DatabaseSeeder.php
User::factory(10)->hasPosts(3)->create();

Section 06

Form Handling & Validation

Validate requests, reuse rules, and surface errors gracefully.

Reminder

Always validate server-side; trust-but-verify client-side constraints.

Inline Validation

Validate inside controllers using the validator helper.

public function store(Request $request)
{
    $data = $request->validate([
        'title' => ['required','string','max:255'],
        'email' => ['required','email'],
        'tags' => ['array'],
        'tags.*' => ['string'],
    ]);

    Post::create($data);
    return back()->with('status', 'Saved');
}

Form Requests

Encapsulate validation/authorization logic.

  • php artisan make:request StorePostRequest
  • rules(): validation rules.
  • authorize(): gate check.
class StorePostRequest extends FormRequest
{
    public function authorize()
    {
        return $this->user()->can('create', Post::class);
    }

    public function rules()
    {
        return [
            'title' => 'required|string|max:255',
            'body' => 'required|string',
        ];
    }
}

Section 07

Middleware & Authentication

Filter requests, secure routes, and scaffold auth.

Security

Combine auth middleware with authorization policies; default guards differ between web and api.

make:middleware

Create middleware and register it.

  • php artisan make:middleware EnsureAdmin
  • app/Http/Kernel.php: add to $routeMiddleware or $middlewareGroups.
// app/Http/Middleware/EnsureAdmin.php
public function handle($request, Closure $next)
{
    abort_unless($request->user()?->is_admin, 403);
    return $next($request);
}

Using Middleware

Apply per route, group, or controller constructor.

// routes/web.php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::get('/dashboard', DashboardController::class)->name('dashboard');
});

// Controller
public function __construct()
{
    $this->middleware('auth');
    $this->middleware('can:update,post')->only('edit','update');
}

Auth Scaffolding

Bootstrapped auth flows for rapid start.

  • Breeze: minimal Tailwind/Blade or Inertia stacks.
  • Jetstream: teams, sessions, 2FA (Blade/Inertia).
  • Sanctum: API tokens/SPAs (guards + middleware).
# Breeze (Blade)
composer require laravel/breeze --dev
php artisan breeze:install blade
npm install && npm run dev

# Sanctum
composer require laravel/sanctum
php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"
php artisan migrate

// Protect API routes
Route::middleware('auth:sanctum')->get('/user', fn($req) => $req->user());

Protecting Routes

Combine auth, throttling, and policies.

  • auth: session or token guard.
  • verified: email verification.
  • throttle:60,1: rate limit.
  • can:view,post: policy checks.
Route::middleware(['auth', 'verified', 'throttle:60,1'])
  ->get('/profile', ProfileController::class)
  ->name('profile');

Section 09

Events, Listeners & Jobs

Decouple domains with events and offload work to queues.

Guideline

Use queues for IO-heavy tasks; keep listeners idempotent and retry-safe.

Events & Listeners

Generate and register event/listener pairs.

  • php artisan make:event UserRegistered
  • php artisan make:listener SendWelcomeEmail --event=UserRegistered
  • EventServiceProvider: map events to listeners.
// Firing an event
UserRegistered::dispatch($user);

// Event payload
class UserRegistered
{
    public function __construct(public User $user) {}
}

Queue Jobs

Dispatch jobs to queues with retry/backoff.

  • php artisan make:job SendReport
  • implements ShouldQueue: marks job as queued.
  • $this->release(): retry later; backoff property.
// Dispatch
SendReport::dispatch($report)->onQueue('reports');

// Worker
php artisan queue:work --queue=reports --timeout=120

// Job example
class SendReport implements ShouldQueue
{
    public $tries = 3;
    public $backoff = 10;
    public function handle(Mailer $mail)
    {
        $mail->to('ops@example.com')->send(new ReportMail);
    }
}

Broadcasting

Send real-time events via websockets/pusher.

  • implements ShouldBroadcast
  • channels.php: define auth callbacks.
  • Broadcast::routes() in routes/channels.php.
// Event example
class OrderShipped implements ShouldBroadcast
{
    public function broadcastOn()
    {
        return new PrivateChannel('orders.'.$this->order->id);
    }
}

Schedules

Automate recurring tasks via scheduler.

  • app/Console/Kernel.php: define schedule() commands.
  • php artisan schedule:run: called every minute via cron.
protected function schedule(Schedule $schedule)
{
    $schedule->command('reports:daily')
      ->dailyAt('06:00')
      ->onFailure(fn() => Log::error('report failed'));
}

Section 10

Config, Caching & Logging

Manage environment, optimize caches, and collect logs.

Note

Never commit .env; prefer config() helpers over env() outside config files.

Environment & Config

Centralize settings in config/ and load via env.

  • env(): use only in config files.
  • config('app.name'): fetch anywhere.
  • php artisan config:cache: cache configuration.
// config/mail.php
'from' => [
  'address' => env('MAIL_FROM_ADDRESS', 'no-reply@example.com'),
  'name' => env('MAIL_FROM_NAME', 'Example'),
],

Caching

Use cache drivers and tags; clear selectively.

  • Cache::put/get/remember/rememberForever
  • Cache::tags(['users'])->flush()
  • php artisan cache:clear: clear default store.
// Cache with ttl (seconds)
Cache::remember('settings', 600, fn() => Setting::all());

Logging

Channels, stacks, and levels via Monolog.

  • config/logging.php: define channels.
  • Log::info|warning|error
  • Stack channels: combine single + slack, etc.
Log::channel('slack')->error('Payment failed', ['order' => $order->id]);

Caching Routes & Views

Optimize route and view loading for prod.

  • php artisan route:cache: requires no route closures.
  • php artisan view:cache: precompile Blade.
  • php artisan route:clear / view:clear: during deploys.
# Typical deploy cadence
php artisan config:cache
php artisan route:cache
php artisan view:cache

Section 11

Testing

Write fast unit tests and expressive HTTP/feature tests.

Hint

Use RefreshDatabase for isolation; prefer factories over fixtures.

php artisan test

Run PHPUnit with Laravel test runner.

  • --filter: run matching tests.
  • --testsuite: unit, feature, etc.
  • --parallel: speed up on multi-core.
php artisan test --testsuite=feature --filter=ProfileTest

Feature Tests

Test HTTP flows with database refresh.

class ProfileTest extends TestCase
{
    use RefreshDatabase;

    public function test_user_can_view_profile()
    {
        $user = User::factory()->create();
        $this->actingAs($user)
             ->get('/profile')
             ->assertOk()
             ->assertSee($user->name);
    }
}

Unit Tests

Isolate pure logic; avoid hitting DB.

class MoneyTest extends TestCase
{
    public function test_can_add_money()
    {
        $a = new Money(500, 'USD');
        $b = new Money(250, 'USD');
        $this->assertEquals(750, $a->add($b)->amount());
    }
}

Pest Support

Use Pest for expressive tests if preferred.

test('guests are redirected', function () {
    $this->get('/dashboard')->assertRedirect('/login');
});

Section 12

Deployment / Workflow Tips

Ship safely with repeatable steps and guarded practices.

Checklist

  • Run tests + lint + static analysis.
  • Migrate with backups; use --force in CI/CD only.
  • Warm caches, queue workers, horizon monitoring.

Release Flow

# CI/CD idea
php artisan test --parallel
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

# Queue workers
php artisan queue:restart  # reload after deploy

# Horizon (if used)
php artisan horizon:terminate

Common Pitfalls

  • Forgetting APP_KEY or cache clears after .env/config changes.
  • Using route closures when route caching is enabled.
  • Not setting trusted proxies/hosts in production.
  • Leaving debug mode on (APP_DEBUG=true) in prod.
  • Running migrations without backups or review.

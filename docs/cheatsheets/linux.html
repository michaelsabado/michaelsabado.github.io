Section 01

Navigation & Paths

Move confidently through the filesystem. Commands respect the current working directory and support relative/absolute paths.

Tip

Use `~` for your home, `.` for current directory, `..` for parent. Quote paths containing spaces.

pwd

Prints the current working directory (resolves symlinks with -P).

Syntax: pwd [options]

  • -L: show logical path (default, respects symlinks).
  • -P: show physical path (resolves symlinks).
# Show logical path
pwd

# Show physical path (resolves symlinks)
pwd -P

cd

Changes directories. Accepts absolute or relative paths and handles shortcuts.

Syntax: cd [path]

  • cd: go to $HOME.
  • cd -: toggle to previous directory.
  • cd ..: move up one level.
  • cd ~/path: target from home.
# Jump to project then return
cd ~/projects/linux-guide
# ...do work...
cd -  # back to prior directory

ls

Lists directory contents. Combine flags for detailed, hidden, and human-readable views.

Syntax: ls [options] [path]

  • -l: long format (permissions, owner, size, time).
  • -a: include hidden entries (dotfiles).
  • -h: human-readable sizes (pairs with -l).
  • -t: sort by modification time (newest first).
  • -r: reverse sort order.
  • -R: recursive listing.
# Detailed view, include hidden, readable sizes
ls -lah

# List newest files first
ls -lt

# Recursively inspect a tree (use carefully in large dirs)
ls -lR /var/log

Section 02

File & Directory Operations

Create, copy, move, and remove files safely. Always double-check destructive commands.

Safety

Pair `-i` (interactive) with commands like `cp`, `mv`, `rm` to avoid accidental overwrites or deletions.

touch

Create empty files or update timestamps.

Syntax: touch [options] file...

  • -a: change access time only.
  • -m: change modification time only.
  • -t [[CC]YY]MMDDhhmm[.ss]: set explicit time.
# Create multiple files
touch README.md notes/todo.txt

# Set a specific timestamp
touch -t 202601011200 logs/app.log

mkdir

Create directories, optionally nested and with specific permissions.

Syntax: mkdir [options] dir...

  • -p: create parent directories as needed (no error if existing).
  • -m MODE: set permissions (octal or symbolic) on creation.
# Create nested path with secure perms (700)
mkdir -p -m 700 /var/www/app/storage/cache

cp

Copy files or directories. Preserve metadata when needed.

Syntax: cp [options] source... target

  • -r / -R: recursive copy (directories).
  • -a: archive mode (preserves perms, times, links; implies -r).
  • -i: prompt before overwrite.
  • -u: copy only when source is newer.
  • -T: treat destination as file (no dir merge).
  • -v: verbose output.
# Preserve metadata while copying a directory
cp -av /etc/nginx /backup/nginx-$(date +%F)

# Copy newer files only
cp -u src/*.sh /usr/local/bin/

mv

Move or rename files/directories. Overwrites target by default.

Syntax: mv [options] source target

  • -i: prompt before overwrite.
  • -n: never overwrite existing.
  • -T: treat destination as normal file.
  • -v: verbose output.
# Rename file safely
mv -i report.txt report-old.txt

# Move tree into archive directory
mv -v ~/logs/2025 ~/archive/logs/

rm

Remove files or directories. Irreversible without backups.

Syntax: rm [options] file...

  • -i: prompt before each removal.
  • -I: prompt once if removing many files or recursive.
  • -r / -R: recursive (required for directories).
  • -f: force (ignore missing; no prompts).
  • -d: remove empty directories.
# Safely remove a directory tree (prompted)
rm -Ir ~/tmp/build

# Dangerous: force remove without prompts
rm -rf /path/to/delete

ln

Create hard or symbolic links. Symlinks are most common.

Syntax: ln [options] target link_name

  • -s: create symbolic link.
  • -f: overwrite existing destination.
  • -n: treat link target as normal file when overwriting symlinks.
# Symlink a config file
ln -s ~/.config/nvim/init.lua ~/project/.nvim.lua

# Replace existing symlink safely
ln -sfn /opt/app/current /var/www/app

Section 03

File Viewing & Search

Read files, page through large outputs, and find content efficiently.

Practice

Pipe commands into pagers (`| less -R`) to keep outputs navigable and searchable.

cat

Concatenate and print files to stdout. Fast for small files.

Syntax: cat [options] file...

  • -n: number all lines.
  • -b: number non-blank lines.
  • -s: squeeze repeated blank lines.
# Show file with line numbers
cat -n /etc/hosts

# Merge multiple files
cat part1.txt part2.txt > combined.txt

less

Pager for large files/streams. Supports search and color output.

Syntax: less [options] file

  • -R: preserve ANSI colors.
  • /pattern: search forward.
  • ?pattern: search backward.
  • n / N: next/prev match.
  • G / g: end/start of file.
  • q: quit.
# View colored log stream
journalctl -u sshd -f | less -R

# Search within file
less /var/log/syslog
/timeout

more

Simple pager, older than less. Use when `less` is unavailable.

Syntax: more [options] file

  • SPACE: next page.
  • ENTER: next line.
  • /pattern: search forward.
more large.txt

head

Show first lines of files. Helpful for quick inspection.

Syntax: head [options] file

  • -n N: show first N lines (default 10).
  • -c N: show first N bytes.
# Preview first 5 lines
head -n 5 config.yaml

tail

Show end of files. Follow live logs with -f.

Syntax: tail [options] file

  • -n N: show last N lines.
  • -f: follow appended data.
  • -F: follow and retry if file is rotated.
# Watch nginx access log with rotation handling
tail -F /var/log/nginx/access.log

grep

Search text using patterns (regex supported). Pipes well with other commands.

Syntax: grep [options] pattern [file...]

  • -i: case-insensitive.
  • -n: show line numbers.
  • -r / -R: recursive search.
  • -v: invert match.
  • -E: extended regex (egrep).
  • -l: list matching file names only.
  • -A/-B/-C N: context after/before/both.
  • -H: show filename prefixes.
  • -m N: stop after N matches per file.
# Recursive search for case-insensitive string with context
grep -RinC2 "timeout" ./config

# Only list files containing pattern
grep -Rl "DATABASE_URL" /etc

find

Locate files/directories by name, type, size, time, or permissions. Executes actions on matches.

Syntax: find path [options] [expression/action]

  • -name/-iname: match (case-sensitive/insensitive).
  • -type f|d|l: file, directory, symlink.
  • -size +100M: size filter (+/- for greater/less).
  • -mtime/-mmin: modified days/minutes ago.
  • -perm 644: permission filter.
  • -exec ... {} \;: run command per match.
  • -print0: NUL-separated output (pair with xargs -0).
  • -exec ... {} +: batch exec with many paths.
  • -maxdepth/-mindepth: limit traversal depth.
# Find large logs and summarize size
find /var/log -type f -name "*.log" -size +200M -exec du -h {} \;

# Delete empty directories safely
find /srv/data -type d -empty -print -delete

# Fix permissions on new files only
find /var/www -type f -mtime -1 -exec chmod 640 {} \;

Section 04

System Information

Inspect kernel, filesystem, memory, and runtime metrics. Useful for troubleshooting and capacity planning.

Hint

Combine these commands with `watch -n 2` for periodic refresh when a tool lacks interactive mode.

uname

Show kernel and system info.

Syntax: uname [options]

  • -a: all info (kernel, node, release, machine, OS).
  • -r: kernel release.
  • -s: kernel name.
  • -m: hardware name (architecture).
# Full system string
uname -a

# Just architecture
uname -m

df

Report filesystem disk usage and mount points.

Syntax: df [options] [path]

  • -h: human-readable units.
  • -T: include filesystem type.
  • -i: show inode usage.
  • -x FSTYPE: exclude filesystem type.
  • --total: show grand total line.
# Check disk and inode usage
df -hT

df -hi  # inode pressure can block writes

du

Summarize directory sizes. Great for finding space hogs.

Syntax: du [options] [path]

  • -h: human-readable units.
  • -s: summary only (top-level total).
  • -d N: max depth N.
  • -x: stay on one filesystem.
# Largest directories in current tree
du -hd1 | sort -h

# Depth-limited view
du -h -d2 /var/www

free

Show memory usage (RAM and swap). Some distros use `procps` version.

Syntax: free [options]

  • -h: human-readable.
  • -m/-g: show in MB/GB.
  • -s N: refresh every N seconds.
# One-time human-readable snapshot
free -h

# Watch memory every 2 seconds
free -h -s 2

top

Interactive process viewer. Available everywhere.

Syntax: top [options]

  • P: sort by CPU.
  • M: sort by memory.
  • k: kill a PID.
  • 1: toggle per-CPU usage.
  • q: quit.
top

htop

Enhanced top with colors, tree view, filtering, and mouse support.

Syntax: htop [options]

  • F5: toggle process tree.
  • F3: search for process.
  • F9: kill with signal menu.
  • F2: setup (hide threads, columns).
# Install then run (Debian example)
sudo apt install -y htop
htop

Section 05

Process Management

List, stop, and foreground/background processes. Signals control behavior.

Warning

Prefer graceful signals (SIGTERM=15) before forcing (SIGKILL=9). Killing critical daemons can destabilize the system.

ps

Snapshot of running processes. Output format varies by options.

Syntax: ps [options]

  • ps aux: BSD style full listing.
  • ps -ef: SysV style full listing.
  • -o columns: custom output (pid,ppid,cmd,%cpu,%mem).
  • --sort: sort by field (eg, -rss).
# Top 5 memory processes
ps -eo pid,ppid,cmd,%mem,%cpu --sort=-%mem | head -n 6

# Find processes by name
ps aux | grep -i "nginx"

kill

Send signals to processes by PID.

Syntax: kill [options] pid...

  • -15 / SIGTERM: graceful stop (default).
  • -9 / SIGKILL: force kill (cannot be trapped).
  • -HUP: hangup/reload (daemons often reload config).
  • -l: list signal names.
  • -s SIGNAL: send specific signal name/number.
# Graceful stop
kill 12345

# Reload service reading new config
kill -HUP 2222

# Force kill runaway process (last resort)
kill -9 9876

killall

Send signals to processes by name. Matches across users unless restricted.

Syntax: killall [options] process_name...

  • -u USER: limit to a user.
  • -I: case-insensitive match.
  • -r regex: regex match.
  • -s SIGNAL: send specific signal.
# Gracefully stop all nginx master/worker processes
sudo killall nginx

# Kill all chrome processes for current user
killall -u "$USER" -I chrome

jobs

List jobs started from the current shell, showing their state and job spec (%1, %2).

Syntax: jobs [options]

  • jobs: basic list.
  • -l: show PIDs with jobs.
  • -p: print only PIDs (one per line).
# Start command then suspend with CTRL+Z
sleep 300
# press CTRL+Z
jobs -l   # view job specs and PIDs
jobs -p   # PIDs only (useful for scripts)

bg

Resume a suspended job in the background so it continues without blocking the shell.

Syntax: bg [%job]

  • bg %n: resume job n (defaults to most recent if omitted).
  • CTRL+Z: suspend current job before using bg.
# Suspend, then continue in background
ping 8.8.8.8
# press CTRL+Z to suspend
bg %1   # continue job 1 in background
jobs    # confirm now "Running" in background

fg

Bring a background job to the foreground so it receives input and displays output interactively.

Syntax: fg [%job]

  • fg %n: foreground job n (defaults to most recent).
  • CTRL+C: stop job; CTRL+Z: re-suspend if needed.
# Bring backgrounded ping back to foreground
fg %1
# interact or stop with CTRL+C when finished

Section 06

Archives & Compression

Bundle files and compress/decompress archives. Mind working directory to avoid path surprises.

Tip

Prefer creating archives from a parent directory and use relative paths to avoid embedding absolute paths.

tar

Create/extract archives; compression via flags.

Syntax: tar [cxtf options] archive.tar[.gz] [paths]

  • -c: create archive.
  • -x: extract archive.
  • -t: list contents.
  • -f FILE: archive file name (required last flag before file).
  • -v: verbose.
  • -z: gzip compression.
  • -j: bzip2 compression.
  • -J: xz compression.
  • -C DIR: change to DIR before action.
  • --strip-components N: drop leading path parts on extract.
# Create gzip archive from parent dir
cd /var/www && tar -czvf /tmp/site.tar.gz site/

# Extract to target directory
tar -xzvf site.tar.gz -C /srv/www

# List contents without extracting
tar -tzf site.tar.gz

gzip

Compress files using the GNU zip format. Replaces original unless -k is used.

Syntax: gzip [options] file...

  • -k: keep original file.
  • -r: recurse directories.
  • -1 ... -9: compression level (1 fastest, 9 smallest).
  • -c: write to stdout (useful for piping).
# Compress and keep original
gzip -k database.sql

# Stream compress then encrypt
tar -cf - /var/www | gzip -c | gpg -c -o backup.tar.gz.gpg

gunzip

Decompress gzip files. Can output to stdout for piping.

Syntax: gunzip [options] file...

  • -k: keep compressed file.
  • -c: write decompressed data to stdout.
  • -t: test integrity only.
# Decompress in place (removes .gz)
gunzip database.sql.gz

# Decompress to stdout and preview first lines
gunzip -c logs.tar.gz | tar -tvf - | head -n 5

zip

Create Zip archives (common on Windows/macOS).

Syntax: zip [options] archive.zip path...

  • -r: recurse directories.
  • -9: maximum compression.
  • -x pattern: exclude files.
  • -q: quiet.
# Zip a folder excluding node_modules
zip -r9 release.zip app/ -x "app/node_modules/*"

unzip

Extract Zip archives.

Syntax: unzip [options] archive.zip

  • -l: list contents.
  • -d DIR: extract to target directory.
  • -o: overwrite without prompts.
  • -q: quiet mode.
# List contents first
unzip -l release.zip

# Extract into /opt/app
sudo unzip -o release.zip -d /opt/app

Section 07

Networking Basics

Check connectivity, transfer files, and interact with remote systems securely.

Note

Many commands respect proxies via environment variables: HTTP_PROXY, HTTPS_PROXY, NO_PROXY.

ping

Send ICMP echo requests to test reachability and latency.

Syntax: ping [options] host

  • -c N: send N packets.
  • -i N: interval seconds between pings.
  • -W N: per-packet timeout (seconds).
  • -4/-6: force IPv4/IPv6.
  • -q: quiet output (summary only).
# Send 4 pings with 0.5s interval
ping -c 4 -i 0.5 1.1.1.1

curl

Transfer data with URLs. Supports HTTP(S), FTP, SCP, etc.

Syntax: curl [options] URL

  • -I: fetch headers only.
  • -L: follow redirects.
  • -o FILE: write output to file.
  • -O: save as remote name.
  • -u user:pass: basic auth.
  • -d data: send POST data.
  • -H: add header (repeatable).
  • --retry N: retry failed transiently.
  • -s: silent (no progress).
  • -k: allow insecure TLS.
  • --connect-timeout N: fail fast if unreachable.
# Check endpoint and follow redirects
curl -IL https://example.com

# POST JSON with custom header
curl -X POST https://api.example.com/items \
  -H "Content-Type: application/json" \
  -d '{"name":"demo"}'

wget

Non-interactive downloader. Good for scripts and mirrors.

Syntax: wget [options] URL

  • -O FILE: save to file.
  • -c: continue partial downloads.
  • -r: recursive (with care).
  • -np: no parent when recursive.
  • --limit-rate: throttle bandwidth.
  • --mirror: mirror site (implies -r -N -l inf -np).
# Resume big download with rate limit
wget -c --limit-rate=2M https://example.com/big.iso -O big.iso

ssh

Secure shell for remote login/commands. Respects ~/.ssh/config.

Syntax: ssh [options] user@host [command]

  • -i key: specify private key.
  • -p port: non-default port.
  • -L local:remote: local port forward.
  • -N: no remote command (port forwarding only).
  • -A: enable agent forwarding.
  • -J host: jump host (ProxyJump).
  • -o option=value: override config (e.g., StrictHostKeyChecking=no).
# Connect with key and custom port
ssh -i ~/.ssh/id_ed25519 -p 2222 admin@server.example.com

# Forward local 8080 to remote 80 (no shell)
ssh -N -L 8080:localhost:80 admin@server

scp

Secure copy over SSH.

Syntax: scp [options] source target

  • -r: recursive copy.
  • -P port: specify SSH port.
  • -i key: private key.
  • -C: enable compression.
  • -3: copy via local host (two-hop scp).
  • -o option=value: pass ssh options (ProxyJump, IdentityFile).
# Upload folder to server
scp -r ./build user@server:/var/www/site

# Download remote log with compression
scp -C user@server:/var/log/app.log ./app.log

Section 08

Package Management

Install, update, remove, and clean packages across popular managers.

Good practice

Update package indexes before installs, and remove caches to reclaim space after large upgrades.

apt (Debian/Ubuntu)

Front-end for APT. Requires sudo for system changes.

Syntax: apt <command> [options] [package...]

  • update: refresh package indexes.
  • upgrade: upgrade packages (no removals).
  • full-upgrade: allow removals (dist-upgrade behavior).
  • install pkg: install package.
  • remove pkg: remove (keep config).
  • purge pkg: remove with config.
  • autoremove: remove unused deps.
  • clean: clear downloaded archives.
# Refresh indexes and upgrade safely
sudo apt update
sudo apt upgrade -y

# Install and then clean cache
sudo apt install -y curl
sudo apt autoremove -y
sudo apt clean

yum / dnf (RHEL/CentOS/Fedora)

`dnf` is the modern replacement for `yum`; commands are largely compatible.

Syntax: dnf|yum <command> [options] [package...]

  • check-update: show available updates.
  • install pkg: install package.
  • remove pkg: uninstall.
  • upgrade: upgrade all packages.
  • clean all: clear caches and metadata.
# Using dnf (Fedora 38+ style)
sudo dnf check-update
sudo dnf install -y git
sudo dnf upgrade -y
sudo dnf clean all

brew (Homebrew, macOS/Linux)

User-space package manager. No sudo required when installed to $HOME.

Syntax: brew <command> [options] [formula]

  • update: fetch latest formula metadata.
  • upgrade [pkg]: upgrade all or specific package.
  • install pkg: install.
  • uninstall pkg: remove formula.
  • cleanup: remove old versions & caches.
  • list: show installed packages.
# Keep brew tidy
brew update
brew upgrade
brew cleanup

# Install CLI then show files
brew install jq
brew list jq -v

Section 09

Text Editors (nano · vi/vim)

Edit files confidently in minimal environments. Understand modes, save flows, and navigation to avoid data loss.

Mac shortcuts

On macOS terminals, use CMD+Arrow for word/line jumps at shell level. Inside editors, use their native keystrokes (listed below).

nano

Beginner-friendly, modeless editor. Commands shown at bottom; use CTRL (^) shortcuts. Auto-saves only when you write, so save frequently.

Open / Save / Exit

Mac/Linux: CTRL+O to write, CTRL+X to exit, CTRL+S toggles safe suspend on some terminals.

# Open file
nano /etc/hosts
# Write changes
^O  # CTRL+O, confirm filename with ENTER
# Exit
^X  # CTRL+X

Search / Replace

^W to search forward; ^\ to search-and-replace. Use regex with -E flag when launching nano.

# Search string
^W timeout ENTER

# Replace string (interactive prompts)
^\ error ENTER
replacement text ENTER

Cut / Copy / Paste

^K cuts current line or selection start; ^U pastes. Mark text with ^6 (CTRL+6) to start a selection, then move cursor.

# Mark block, cut, then paste
^6        # set mark
(move with arrows)
^K        # cut selection
^U        # paste at cursor

Common Pitfalls

  • SSH sessions: enable keepalive (ServerAliveInterval) to avoid losing unsaved edits.
  • Readonly files: use `sudo nano file` or write to temp and `sudo tee` to save.
  • Accidentally frozen? Press CTRL+Q to resume XON/XOFF flow control.

vi / vim

Modal editor. Normal mode for commands, Insert mode for typing, Visual for selections, Command-line mode for ex commands. Master mode switching to stay efficient.

Modes & Switching

  • Normal (default): navigation/commands. Return via ESC or CTRL+[.
  • Insert: i (before cursor), a (after), o (new line), I/A/O variants for line ends/starts.
  • Visual: v (char), V (line), CTRL+V (block).
  • Command-line: : to run ex commands (write/quit/substitute).

Save / Quit

:w        # write file
:q        # quit (fails if unsaved)
:wq       # write and quit
:x        # write if changed, then quit
:q!       # force quit discard changes
:w newfile# save to new path
:wa       # write all buffers

Navigation

h j k l   # left/down/up/right
w / b     # next/prev word
0 / $     # line start / end
G / gg    # end / start of file
:number   # jump to line
/needle   # search forward
n / N     # next / prev match
CTRL+u/d  # half-page up/down
%         # match brackets
* / #     # search word under cursor

Edit, Yank, Paste

yy    # yank (copy) line
2yy   # yank 2 lines
p / P # paste below / above
dd    # delete line (cut)
dw    # delete word
ci"   # change inside quotes
vi(   # select inside parentheses
"+p   # paste from system clipboard (if enabled)
"+yy  # copy to system clipboard

Search & Replace

:%s/old/new/g        # replace all in file
:%s/old/new/gc       # confirm each
:'<,'>s/old/new/g    # replace in visual selection
:argdo %s/old/new/g  # replace across files (args list)

# Case-insensitive search
:set ignorecase
:set smartcase       # ignorecase unless pattern has uppercase

Workflow Examples

# Edit config, search, replace, save
vim /etc/nginx/nginx.conf
/worker_connections   # find directive
n                     # next match
ciw 4096              # change number
:wq                   # save + exit

# Open multiple files, write all
vim app.py settings.py
:bn / :bp             # next/prev buffer
:wa                   # write all
:q                    # quit after saving

Common Pitfalls

  • Stuck in Insert? Press ESC; if terminal echoes `^ [`, use CTRL+[ instead.
  • No write permission: `:w !sudo tee %` (vim) to save with sudo without reopening.
  • Swap/lock files after crash: remove .swp only after verifying no other instance is editing.

Section 10

Permissions & Ownership

Control who can read, write, and execute files/directories. Understand numeric vs symbolic modes and apply secure defaults.

Warning

Avoid `chmod 777`. It grants full access to everyone and can expose credentials, SSH keys, or executables to tampering.

Permission Model

Modes apply to user (u), group (g), others (o). Bits: read (4), write (2), execute (1). Directories require execute to traverse.

Numeric Symbolic Meaning Common Use
700u=rwx, g=---, o=---Owner full, no one else.Private scripts, SSH keys.
600u=rw-, g=---, o=---Owner read/write.Secrets, SSH private keys.
644u=rw-, g=r--, o=r--Owner read/write; others read.Default for text/config files.
755u=rwx, g=rx, o=rxOwner full; others read/execute.Executable directories, binaries.
775u=rwx, g=rwx, o=rxOwner+group full; others read/execute.Shared web roots with deploy group.
777u=rwx, g=rwx, o=rwxEveryone full access.Avoid except temp dirs with strict isolation.

Directories: execute bit controls entering/traversing; read bit controls listing; write allows creating/removing entries when execute is also set.

chmod

Change file or directory mode. Supports numeric and symbolic forms.

Syntax: chmod [options] mode path...

  • Numeric: 755, 644, 600, etc.
  • Symbolic: u+x, g-w, o=rx, a+rX.
  • -R: recursive apply.
  • X: execute only if directory or already executable (safe recursive flag).
# Secure private key
chmod 600 ~/.ssh/id_ed25519

# Make script executable for owner only
chmod 700 deploy.sh

# Recursively set web root with safe execute
chmod -R a+rX /var/www/site

# Add group write for shared storage
chmod -R g+w /var/www/site/storage

chown

Change ownership (user and optionally group). Requires sudo for system files.

Syntax: chown [options] owner[:group] path...

  • user:group: set both.
  • :group: set group only.
  • -R: recursive.
  • -h: affect symlink itself (not target).
# Transfer ownership to deploy user
sudo chown -R deploy:deploy /var/www/site

# Fix symlink owner only
sudo chown -h root:root /usr/local/bin/app

chgrp

Change group ownership. Useful with shared directories.

Syntax: chgrp [options] group path...

  • -R: recursive.
  • -h: affect symlink itself.
# Assign group to shared cache
sudo chgrp -R www-data /var/www/site/storage

# Combine with chmod for group collaboration
sudo chmod -R 775 /var/www/site/storage

Real-World Scenarios

# SSH keys (private, no group/other access)
chmod 600 ~/.ssh/id_ed25519

# Web server root: allow deploy group to write, world read
sudo chown -R deploy:www-data /var/www/site
sudo chmod -R 775 /var/www/site

# Laravel storage bootstrap cache writable by web user

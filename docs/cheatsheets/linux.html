Additional References: Linux Permissions

Quick cues for decoding permission strings, choosing chmod defaults, and keeping ownership tidy.

Permissions fast-lane

Permissions overview

Linux assigns every file and directory a trio of rights — read (r), write (w), execute (x) — scoped to user (u), group (g), and others (o). Users own the files they create, groups are team buckets, and others is everyone else. Execute means “run” when it’s a file, or “enter/traverse” when it’s a directory.

Permission notation

Symbolic strings such as rwxr-xr-- read left to right (user/group/others). Numeric (octal) notation sums bit values (r=4, w=2, x=1) per trio, so 755 equals rwxr-xr-x.

w = 2

x = 1

Common chmod usage

4 quick cards

chmod 755 file

Owner can modify; others can read/execute.

Use when

CLI tools, shared scripts in repos.

chmod 644 file

Writable owner, read-only world.

Use when

Static assets, configs, docs.

chmod +x script.sh

Adds execute bit to current user/group/others.

Use when

Making build/deploy scripts runnable.

chmod -R 755 directory/

Apply 755 to all items recursively.

Use when

Publishing webroots or CLI bundles.

chown user file

Transfer ownership to another account.

Why

CI/CD artifacts or service users must own what they run.

chown user:group file

Set both owner and group in one shot.

Why

Deploy folders shared by web + worker roles.

chgrp group file

Switch the team that inherits group rights.

Why

Hand off shared storage to a different squad.

Quick tips & gotchas

  • 777 opens full control to everyone — avoid on shared servers.
  • Execute on files means “run”; on directories it allows traversal and powering cd.
  • -R is convenient but destructive — double-check the root path before cascading.
  • Defaults come from umask; stricter umasks (e.g., 027) prevent overly permissive new files.

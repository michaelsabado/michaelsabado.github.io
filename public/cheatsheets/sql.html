01

Database Basics

Bootstrap databases and inspect schemas.

CREATE DATABASE

Create schema container.

CREATE DATABASE app_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  • IF NOT EXISTS — Skip error when re-running.
  • Specify charset/collation to avoid legacy latin1 defaults.

USE

Choose active database.

USE app_db;

Required before referencing tables without schema prefix.

SHOW DATABASES

List accessible schemas.

SHOW DATABASES LIKE 'app%';

Use LIKE to filter large environments.

SHOW TABLES

View tables in current DB.

SHOW TABLES FROM app_db;

Prefix with schema if not using USE.

02

Table Operations

Define, inspect, and restructure tables safely.

CREATE TABLE

CREATE TABLE users (
  id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(255) NOT NULL UNIQUE,
  name VARCHAR(120),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
  • Choose InnoDB for FK support.
  • Set explicit sizes and defaults.

DROP TABLE

DROP TABLE IF EXISTS audit_log;

Irreversible. Wrap in transactions where supported or back up first.

ALTER TABLE

ALTER TABLE users
  ADD COLUMN last_login DATETIME NULL AFTER name,
  MODIFY email VARCHAR(320) NOT NULL;

Plan for locking. MySQL 8 online DDL helps but not universal.

TRUNCATE TABLE

TRUNCATE TABLE staging_import;

Faster than DELETE; resets AUTO_INCREMENT. Non-transactional.

DESCRIBE

DESCRIBE users;
-- alias: EXPLAIN users;

Shows column types, nullability, keys, defaults.

03

Data Manipulation

Insert, update, delete, and query data with precision.

INSERT INTO

INSERT INTO users (email, name)
VALUES ('dev@example.com', 'Dev Ops'),
       ('cto@example.com', 'CTO');
  • INSERT ... SELECT — Copy from other tables.
  • ON DUPLICATE KEY UPDATE — Upsert pattern.

UPDATE

UPDATE users
SET name = 'Support'
WHERE email = 'support@example.com';

Always include WHERE unless intentional bulk update. Use LIMIT to test.

DELETE FROM

DELETE FROM sessions
WHERE created_at < NOW() - INTERVAL 30 DAY
LIMIT 1000;

Chunk deletes with LIMIT to avoid long locks.

SELECT basics

SELECT DISTINCT name, role
FROM users
WHERE active = 1 AND role IN ('admin','ops')
ORDER BY name ASC
LIMIT 10 OFFSET 20;
  • DISTINCT — Remove duplicates.
  • ORDER BY column ASC|DESC.
  • LIMIT X OFFSET Y — Pagination.

Predicate helpers

SELECT * FROM orders
WHERE created_at BETWEEN '2026-02-01' AND '2026-02-07'
  AND status IN ('paid','fulfilled')
  AND reference LIKE 'INV%'
  AND shipped_at IS NULL;

Use BETWEEN inclusive for ranges, IN for lists, LIKE with % wildcard, IS NULL / IS NOT NULL for tri-state fields.

Common pitfalls

  • Missing WHERE in UPDATE/DELETE wipes whole table.
  • COUNT(*) ignores WHERE if mistakenly omitted.
  • LIKE '%term%' prevents index use; prefer full-text or prefix search.

04

Joins

Combine rows across tables for richer views.

Standard joins

SELECT u.name, o.total
FROM users u
INNER JOIN orders o ON o.user_id = u.id
WHERE o.status = 'paid';

SELECT u.name, o.total
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;

SELECT u.name, o.total
FROM users u
RIGHT JOIN orders o ON o.user_id = u.id;

INNER returns matches only; LEFT keeps left rows; RIGHT keeps right rows.

Full & special joins

-- MySQL lacks FULL OUTER JOIN; emulate with UNION
SELECT ... FROM users u LEFT JOIN orders o ON ...
UNION
SELECT ... FROM users u RIGHT JOIN orders o ON ...
WHERE u.id IS NULL;

-- CROSS JOIN
SELECT u.name, p.plan_name
FROM users u CROSS JOIN plans p;

-- Self join
SELECT e.name, m.name AS manager
FROM employees e
JOIN employees m ON e.manager_id = m.id;

Use explicit aliases, always specify join predicates to avoid accidental Cartesian products.

05

Aggregations

Summaries, counts, and grouped analytics.

Aggregate functions

SELECT COUNT(*) AS total_orders,
       SUM(total) AS revenue,
       AVG(total) AS avg_order,
       MIN(created_at) AS first_order,
       MAX(created_at) AS last_order
FROM orders;

Aggregates ignore NULL except COUNT(*). Use COUNT(column) to skip NULL rows.

GROUP BY & HAVING

SELECT user_id,
       COUNT(*) AS orders,
       SUM(total) AS revenue
FROM orders
WHERE status = 'paid'
GROUP BY user_id
HAVING SUM(total) > 1000
ORDER BY revenue DESC
LIMIT 20;

HAVING filters aggregated results; WHERE filters input rows. Use indexes on WHERE columns for performance.

06

Subqueries

Embed queries for filtering, comparisons, and existence checks.

Scalar & IN subqueries

SELECT name,
       (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS order_count
FROM users u;

SELECT *
FROM orders
WHERE user_id IN (
  SELECT id FROM users WHERE role = 'vip'
);

Scalar subquery must return one value; IN subqueries can return many rows.

EXISTS & correlated

SELECT u.*
FROM users u
WHERE EXISTS (
  SELECT 1 FROM subscriptions s
  WHERE s.user_id = u.id AND s.active = 1
);

SELECT o.*
FROM orders o
WHERE o.total > (
  SELECT AVG(total) FROM orders o2
  WHERE o2.user_id = o.user_id
);

EXISTS stops after first match; correlated subqueries run per row—ensure proper indexes.

07

Indexes & Keys

Define primary keys, foreign keys, and performance indexes.

Primary & auto increment

id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT;

Single-column PK ensures uniqueness and clustering. Use BIGINT to avoid overflow.

Foreign key

CONSTRAINT fk_orders_user
  FOREIGN KEY (user_id)
  REFERENCES users(id)
  ON DELETE CASCADE
  ON UPDATE RESTRICT;

Ensures referential integrity. Cascades delete child rows automatically.

Unique & secondary indexes

CREATE UNIQUE INDEX idx_users_email ON users(email);
CREATE INDEX idx_orders_status_created
  ON orders(status, created_at DESC);

Order columns by selectivity; prefix indexes cover leading columns only.

08

Transactions

Group statements atomically for consistency.

Begin / commit / rollback

START TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT; -- use ROLLBACK on error

Autocommit is on by default; start transaction to group statements. Use ROLLBACK on failure.

Savepoints

START TRANSACTION;
SAVEPOINT before_bonus;
UPDATE employees SET bonus = bonus * 1.1;
ROLLBACK TO SAVEPOINT before_bonus;
COMMIT;

Use SAVEPOINT to undo part of a transaction without aborting entire block.

09

Views

Encapsulate reusable queries.

CREATE VIEW

CREATE VIEW active_users AS
SELECT id, email
FROM users
WHERE active = 1 WITH CHECK OPTION;

WITH CHECK OPTION prevents inserts/updates violating view WHERE clause.

Use view

SELECT * FROM active_users ORDER BY email;

Treat like table. Complex views may prevent updates.

DROP VIEW

DROP VIEW IF EXISTS active_users;

Drop and recreate to refresh definitions; MySQL lacks CREATE OR REPLACE prior to 5.7.7.

10

Stored Procedures & Functions

Package logic within the database.

Procedures

DELIMITER $$
CREATE PROCEDURE recent_orders(IN days_back INT)
BEGIN
  SELECT * FROM orders
  WHERE created_at >= NOW() - INTERVAL days_back DAY;
END $$
DELIMITER ;
CALL recent_orders(7);
DROP PROCEDURE IF EXISTS recent_orders;

Switch delimiters to define multi-line bodies. Procedures can modify data.

Functions

DELIMITER $$
CREATE FUNCTION net_total(gross DECIMAL(10,2), rate DECIMAL(5,2))
RETURNS DECIMAL(10,2) DETERMINISTIC
BEGIN
  RETURN gross * (1 - rate);
END $$
DELIMITER ;
SELECT net_total(100, 0.15);
DROP FUNCTION IF EXISTS net_total;

Functions must return a value and cannot modify tables when deterministic.

11

Constraints

Ensure data quality at the schema level.

NOT NULL & DEFAULT

price DECIMAL(8,2) NOT NULL DEFAULT 0.00;

Enforce presence and provide fallback values.

UNIQUE & CHECK

UNIQUE KEY uk_slug (slug);
CHECK (quantity >= 0);

MySQL 8 enforces CHECK constraints; earlier versions ignore them.

FOREIGN KEY recap

FOREIGN KEY (post_id) REFERENCES posts(id) ON DELETE CASCADE;

Requires indexed parent column. Choose CASCADE/SET NULL/RESTRICT carefully.

12

Advanced / Utilities

Handy expressions and functions for day-to-day SQL.

CAST / CONVERT

SELECT CAST(total AS DECIMAL(10,2)) AS amount
FROM orders;

Use to force numeric/date comparisons when mixing types.

COALESCE / IFNULL

SELECT COALESCE(nickname, name, 'Unknown') AS display_name FROM users;

COALESCE handles multiple fallbacks; IFNULL is two-argument shortcut.

CASE expressions

SELECT order_id,
       CASE
         WHEN total >= 500 THEN 'VIP'
         WHEN total >= 100 THEN 'Premium'
         ELSE 'Standard'
       END AS tier
FROM orders;

Use CASE for conditional labels or calculations inline.

Date & string helpers

SELECT DATE_FORMAT(created_at, '%Y-%m') AS month,
       CONCAT(first_name, ' ', last_name) AS full_name,
       TIMESTAMPDIFF(DAY, created_at, NOW()) AS age_days
FROM users;

Prefer server-side formatting for reports; keep raw timestamps for application logic.

LIMIT & OFFSET

SELECT * FROM orders
ORDER BY created_at DESC
LIMIT 50 OFFSET 100;

Large offsets get slow; consider keyset pagination (WHERE id < ?).

13

Admin Commands

Diagnose performance and permissions.

SHOW PROCESSLIST

SHOW FULL PROCESSLIST;

Displays running queries. Kill long blockers via KILL id;

SHOW GRANTS

SHOW GRANTS FOR 'app'@'localhost';

Audit user permissions quickly.

EXPLAIN SELECT

EXPLAIN ANALYZE SELECT * FROM orders WHERE status = 'paid';

Shows execution plan. Look for "Using where" and avoid "Using filesort" without indexes.

SHOW STATUS

SHOW GLOBAL STATUS LIKE 'Threads%';

Monitor server metrics such as Threads_connected.

SHOW VARIABLES

SHOW VARIABLES LIKE 'innodb_buffer_pool_size';

Verify runtime configuration.

FLUSH privileges

FLUSH PRIVILEGES;

Reload grants after manual edits to mysql.* tables.

14

Tips & Gotchas

Avoid common production surprises.

Security & data integrity

  • Prevent SQL injection: always bind parameters (? / :name) instead of interpolating strings.
  • NULL ≠ empty string. Use IS NULL checks and default columns explicitly.
  • Grant least privilege: SELECT-only users cannot accidentally mutate data.

Performance reminders

  • Index columns used in JOIN, WHERE, ORDER BY, and foreign keys.
  • Composite indexes follow leftmost prefix rule—reorder columns to match query patterns.
  • MySQL comparisons are case-insensitive for default collations; use COLLATE utf8mb4_bin for case-sensitive searches.
  • Use EXPLAIN ANALYZE before deploying new queries to confirm plan.
Keep this cheatsheet nearby for day-to-day SQL work. Validate destructive statements with WHERE + LIMIT, index selectively, and always test on staging before production runs.

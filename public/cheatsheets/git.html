01

Git Basics

Initialize repositories, inspect status, add files, craft commits, and compare changes.

7 commands

git init

Create a new repository.

Start

Usage

git init --initial-branch=main
  • --bare — Create repo without working tree (server-side).
  • --initial-branch — Name the first branch.

Use when bootstrapping new projects or re-initializing after removing .git.

git clone

Copy an existing repo.

Core

Usage

git clone https://github.com/org/app.git app
  • --depth 1 — Shallow clone for CI or quick review.
  • --branch feature — Checkout a remote branch directly.
  • --recurse-submodules — Initialize nested repos.

Use when onboarding to an existing project or mirroring repos.

git status

View working tree state.

Inspect

Usage

git status -sb
  • -s / -sb — Short output with upstream info.
  • --ignored — Show ignored files.

Run before committing or switching branches to avoid surprises.

git add

Stage file changes.

Stage

Usage

git add src/**/*.ts
  • -p — Stage hunks interactively.
  • -u — Stage tracked file updates & deletions.
  • --all — Stage everything (tracked + untracked).

Use to curate commits; pair with -p for surgical staging.

git commit

Record staged changes.

Record

Usage

git commit -m "feat: add onboarding flow"
  • -a — Automatically stage tracked files.
  • --amend — Replace previous commit (use cautiously).
  • --no-verify — Skip hooks (only when necessary).

Use for atomic changes; craft meaningful messages to simplify reviews.

git log

Inspect commit history.

History

Usage

git log --oneline --decorate --graph --all
  • --oneline — Compact output.
  • --graph — ASCII branch graph.
  • --since="3 days ago" — Filter by time.

Use for quick audits, release notes, or to confirm merges.

git diff

Compare changes.

Compare

Usage

git diff HEAD~1..HEAD --stat
  • --staged — Diff staged changes.
  • --stat — Summary of insertions/deletions.
  • branchA..branchB — Compare histories.

Use before PRs or code reviews to understand impact.

02

Branching & Navigation

Create, inspect, switch, and align branches safely.

git branch

List & manage branches.

Navigate 
git branch -a
  • -a — Show local + remote branches.
  • -d/-D — Delete (safe/force) branch.
  • -m — Rename current branch.

Use to audit available branches or clean stale ones.

git switch

Move between branches.

Navigate 
git switch develop
  • --discard-changes — Drop local modifications.
  • --detach — Enter detached HEAD intentionally.

Use instead of checkout for clarity.

git switch -c

Create + switch.

Create 
git switch -c feature/auth-ui origin/main
  • -c new — Start new branch from current tip.
  • start-point — Optional base ref.

Use when starting feature work with a clean base.

git checkout (legacy)

Older switch/create syntax.

Legacy 
git checkout -b hotfix/login main
  • git checkout file — Restore file from HEAD.
  • git checkout — Detached HEAD.

Use only when scripts/tools still rely on checkout.

git merge

Combine histories.

Integrate 
git merge feature/payment
  • --no-ff — Force merge commit for traceability.
  • --squash — Combine changes without auto-commit.

Use when integrating reviewed branches; resolve conflicts before committing.

git rebase

Replay commits onto another tip.

Advanced 
git rebase origin/main
  • -i HEAD~3 — Interactive rewrite for cleanup.
  • --onto main feature base — Move subset of commits.
  • --rebase-merges — Preserve branch structure.

Use to maintain linear history. Avoid rebasing shared/public branches.

03

Remote Repositories

Coordinate with origin servers and shared remotes.

git remote -v

Show remotes & URLs.

git remote -v
  • git remote add upstream ... — Track another source.
  • git remote set-url origin ... — Update URL (HTTPS⇄SSH).

Use when auditing push/pull URLs or configuring forks.

git fetch

Download refs only.

git fetch origin --prune
  • --all — Fetch every remote.
  • --prune — Remove deleted remote branches.
  • origin feature — Fetch a single branch.

Use before comparing or rebasing to stay current.

git pull

Fetch + merge/rebase.

git pull --rebase origin main
  • --rebase — Avoid merge commits for local sync.
  • --ff-only — Fail if merge commit required.

Use for daily sync; configure default strategy in git config pull.rebase true.

git push

Upload local refs.

git push origin feature/docs
  • --set-upstream / -u — Link local branch to remote.
  • --force-with-lease — Force push with safety check.

Use to publish work for review, CI, or release.

git push -f

Overwrite remote history.

Warning 
git push --force-with-lease origin feature
  • --force — Blunt force; may erase teammates' work.
  • --force-with-lease — Safer: fails if remote advanced.

Use only after rebasing private branches. Announce before force pushing shared branches.

04

Stashing

Shelve work-in-progress without committing.

git stash

Save dirty state.

git stash push -m "WIP: auth flow" --include-untracked
  • -m — Give stash a label.
  • --include-untracked — Save new files too.
  • --keep-index — Keep staged changes staged.

Use before switching branches mid-task.

git stash list

View saved stashes.

git stash list --stat
  • --stat — Show summary of each stash.

Use to choose which stash to reapply.

git stash apply

Reapply without removing.

git stash apply stash@{2}
  • --index — Restore staged state.

Use when you may need the same stash again or want to test before popping.

git stash pop

Apply & delete.

git stash pop
  • --index — Restore staged state.

Use after verifying the target branch; conflicts behave like merges.

05

Undo & Fix Mistakes

Recover from accidents, rewrite commits responsibly, and fix branch mix-ups.

git restore

Discard working tree changes.

git restore src/app.js
  • --source HEAD~1 — Restore from older commit.
  • --worktree — Default; affects files only.

Use to drop local modifications in specific files.

git restore --staged

Unstage without losing work.

git restore --staged package.json
  • --worktree — Combine to drop staged + working tree.

Use when you staged something prematurely.

git reset --soft

Move HEAD, keep staging.

git reset --soft HEAD~1
  • target — Commit to move to (HEAD~1, abc123).

Use to rewrite latest commit while keeping staged snapshot.

git reset --mixed

Default reset: unstage changes.

git reset HEAD^

Use to move commits back into working tree for editing.

git reset --hard

Discard staged + working changes.

git reset --hard origin/main

Use only when you're certain uncommitted work can be lost. Back up critical files first.

git revert

Create inverse commit.

git revert HEAD~2
  • --no-edit — Keep default message.
  • -m 1 — Choose parent for reverting merges.

Use on shared branches to undo commits without rewriting history.

Amend last commit

Fix message or include forgotten changes.

git commit --amend --no-edit
# or update message
git commit --amend -m "feat: clarify API"

Use before pushing to remote. After pushing, coordinate with team and force push safely.

Fix commit on wrong branch

Move work to intended branch.

git switch correct-branch
# cherry-pick commit
git cherry-pick 
git switch wrong-branch
git reset --hard HEAD~1

Use to salvage commits made on main or another branch. Cherry-pick keeps history clean.

Reset comparison

Command HEAD moves? Staging area Working tree
reset --soft Yes Preserved Preserved
reset --mixed Yes Cleared Preserved
reset --hard Yes Cleared Discarded

06

History & Inspection

Trace authorship, compare diffs, and inspect commits quickly.

git log --oneline

Compact history.

git log --oneline --decorate --max-count=15
  • --decorate — Show refs.
  • --author="Alex" — Filter by author.

Use for quick release summaries or to find commit IDs.

git log --graph

Visualize branching.

git log --graph --oneline --all --color

Use to explain branch topology during reviews or debugging.

git show

Display commit details.

git show HEAD~1 --stat --patch
  • --name-only — List touched files.
  • --name-status — Show add/modify/delete.

Use to inspect a specific commit before cherry-picking or reverting.

git blame

Annotate file history.

git blame -L 20,60 --date=short src/server.ts
  • -L start,end — Limit to line range.
  • -w — Ignore whitespace.

Use when tracking regressions or understanding context; pair with git show.

07

Tags

Mark releases and important checkpoints.

git tag

List or create lightweight tags.

git tag v1.4.0

Use for local markers or automation scripts.

git tag -a

Annotated tag with metadata.

git tag -a v1.5.0 -m "Release 1.5"
  • -s — Sign tag with GPG.

Use for releases so tag includes author, date, and message.

git push --tags

Publish tags.

git push origin --tags
# or single tag
git push origin v1.5.0

Use after tagging releases so CI/CD or teammates can access them.

08

Common Workflows

Battle-tested patterns for collaborating at scale.

Feature branches

Start from main, branch per unit of work, rebase or merge main frequently, open PR when ready.

git fetch origin
git switch -c feature/payment origin/main

Pull request flow

Push branch, open PR, ensure CI passes, squash merge for tidy history, delete branch.

git push -u origin feature/payment
# after review
git switch main && git pull --rebase

Hotfix flow

Branch from production tag, patch urgently, merge back into both main and release branches, tag release.

git switch -c hotfix/cache v1.4.3
# fix + commit
git tag v1.4.4 && git push --tags

09

Git Config

Set identity, editors, and inspect settings.

user.name

git config --global user.name "Alex Kim"

Use per machine; override per repo without --global.

user.email

git config --global user.email "alex@example.com"

Use GitHub noreply if privacy is required.

core.editor

git config --global core.editor "code --wait"

Ensures commit messages open in VS Code and wait until closed.

Config list

git config --show-origin --list

Shows value plus file source (/etc/gitconfig, global, repo).

11

SSH & Authentication

Securely connect to remotes.

Generate SSH key

ssh-keygen -t ed25519 -C "alex@example.com"
# add to agent
ssh-add ~/.ssh/id_ed25519

Use modern algorithms (ed25519) and protect with a passphrase.

Test SSH access

ssh -T git@github.com

Expect "You've successfully authenticated" message; failure hints at missing keys.

HTTPS vs SSH

HTTPS — Simple, works behind strict proxies, can use PAT tokens.

SSH — Key-based, no password prompts, required for signed pushes.

Choose based on network restrictions and security requirements.

12

Common Problems & Fixes

Diagnose frequent Git headaches fast.

Detached HEAD

Occurs when checking out a commit SHA. Create a branch before committing.

git switch -c temp-fix
# commit safely

Merge conflicts

Open conflicting files, look for <<<<<<< markers, resolve, then continue.

git status
# edit files
git add resolved-file
git merge --continue

Push rejected

Remote advanced. Pull with rebase, resolve, push again.

git fetch origin
git pull --rebase origin main
# or force-with-lease after coordination

Line ending issues

Configure autocrlf or .gitattributes for consistent endings.

git config --global core.autocrlf input
# or .gitattributes
*.sh text eol=lf

Git Aliases

Shortcuts for daily commands.

Define aliases

git config --global alias.st status -sb
git config --global alias.co switch
git config --global alias.unstage "restore --staged"

Aliases behave like subcommands: git st.

Helpful examples

git config --global alias.lg "log --graph --oneline --all"
git config --global alias.rbi "rebase -i"
git config --global alias.last "show -1 --stat"

Use descriptive names to document your workflow for teammates.
